# CountyIQ optimization audit — September 6, 2026

Optimize the amount of work performed and the cost of maintaining it first. Keep Python, FastAPI, Dagster, React, and PostgreSQL/PostGIS as the baseline. The strongest opportunities are bounded ingestion, bulk database operations, smaller map responses, fewer repeated requests, and simpler verification. A narrow native worker remains a credible experiment; a wholesale rewrite currently lacks supporting measurements.

Scope: repository audit against HEAD `46c48db` plus the existing dirty working tree, including in-progress experiments. This is a prioritized discovery assessment, not a line-by-line correctness/security certification or a production capacity test. Application code, deployment, schema, and existing changes were left untouched. Prior measurements are labeled below; proposed gains are unmeasured unless stated otherwise.

**What is already working**

- API connection pooling, bounded pool waits, database role statement timeouts, separate runtime roles, container restrictions, and pinned images/dependencies already exist. Adding these again is not an optimization.
- Parcel ingestion already uses bounded parallel pages, incremental archives, completeness checks, temporary-table indexing, and `ANALYZE`.
- Frontend routes already load lazily. Shared page fetching already cancels obsolete requests; the custom map fetch paths are the exception identified here.
- CI already includes API/pipeline unit and database contracts, frontend typechecking/lint/build, formatting, dependency audits, secret scanning, and deployment checks.
- Recovery tooling already uploads and verifies database backups. Intelligence already has cost ceilings, provenance checks, rejection records, and cached deterministic feed generation. Preserve these controls.

**Language, runtime, and tool choices**

| Candidate | Decision for this repository | Promotion condition / migration cost |
| --- | --- | --- |
| Python + FastAPI + Dagster | Keep; optimize SQL, data lifetime and requests first. | Replacing orchestration/API means porting substantial semantics and operations. No measured orchestration or HTTP-runtime bottleneck was established. |
| Newer CPython | Schedule a compatibility evaluation; API currently constrains Python to 3.11, while pipelines allow 3.11+. | Python 3.11 is in security-only maintenance. Upgrade locks, images, CI and native dependencies together; benchmark representative jobs. Lifecycle work, with speed gains to be measured. |
| Native Rust | Retain the existing narrow worker experiment. | Promote only after full ingestion equivalence and repeated end-to-end CPU/RSS wins outweigh another toolchain/interface. |
| Go/Rust/TypeScript backend rewrite | Defer. | Require evidence that replaceable application CPU dominates and cannot be reduced economically within the current stack. Database/provider latency remains after a rewrite. |
| Wasm | Defer until browser computation or untrusted plugin isolation is required. | Adds boundary/runtime work; the current workload supplies no measured requirement. See the existing [runtime assessment](/home/jdaws/countyiq/docs/research/wasm-runtime-assessment-2026-09-05.md). |
| Vector tiles | Strong map experiment after measuring payloads. | New endpoint/rendering/cache integration; retain string PIDNs, exact detail geometry and permission checks. PostGIS can generate MVT directly. |
| Redis, Kafka, Kubernetes, microservices | No demonstrated requirement in this audit. | Add only for a measured shared-state, queueing or operational need; each adds deployment, failure and recovery responsibilities. |
| Async DB driver, PgBouncer | Conditional, not the first API change. | Existing sync routes and bounded pool are coherent. Revisit after measuring pool wait/connection churn and concurrency; an async conversion spans driver, helpers and callers. |
| Shared frontend query library | Evaluate if dedupe/invalidation needs spread beyond metadata. | Start with a small metadata provider; avoid creating an extensive homegrown query framework. Account-specific cache isolation is mandatory. |
| Managed PostgreSQL | Operational tradeoff, not an assumed speedup. | Compare actual backup/on-call effort, PostGIS support, storage/egress, restore targets and migration downtime against current hosting cost. |
| Broader parallel Dagster execution | Keep the one-run guard until capacity evidence supports a change. | Current container limits share a small host. Classify asset resource needs and lock interactions before increasing concurrency. |

The existing [ArcGIS benchmark](/home/jdaws/countyiq/benchmarks/arcgis-ingestion/README.md:17) records one live-source run per candidate: buffered Python 1.27 GiB/50.72 s, bounded Python 160 MiB/35.58 s, Rust with gzip 49 MiB/30.94 s. Bounded Python is already in production source. These are fetch-only implementation comparisons with network/compression confounders, not a language-only or end-to-end speed guarantee. The remaining Rust opportunity is credible memory headroom, not a demonstrated reduction in the fixed hosting bill.

**Execution and stopping rule**

Start with baseline capture, planning-subdivision lookup/archive fixes, geometry-loader batching, stale map cancellation and CI consolidation. Next run the `COPY` and map-payload experiments, then address request fan-out and contract generation. Revisit runtime and infrastructure choices with the resulting measurements.

Every performance change needs a before/after workload, correctness oracle, resource/cost comparison and rollback path. Use source-complete fixtures with expected removal/null/duplicate cases for ingestion; realistic cardinalities and mixed traffic for SQL; representative devices and permissions for browser behavior. Promote improvements that reduce user latency, resource pressure, operating cost or maintenance burden. Stop when the next improvement costs more in complexity and verification than it returns. Production manageability is an optimization objective too.
